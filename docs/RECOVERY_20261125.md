## Hai hồ sơ được chọn

Retrofit có lỗi cụ thể, sửa được bằng cấu hình: POM gốc khai báo Kotlin 1.2.60 nhưng plugin không có version, khiến Maven chọn 2.5.0-RC không phù hợp JDK8. Lượt mới chỉ thêm `<version>${kotlin.version}</version>` vào POM bản build tạm. Receipt lưu diff và băm trước/sau; source Java trong Git và nhãn không đổi. Hai snapshot đều package PASS.

Jenkins Global Shared Library được chọn vì log cũ dừng ở kiểm tra repository ID của dependency trong cache. Lượt offline xác định thiếu BOM `io.jenkins.tools.bom:bom-weekly:1008.vb9e22885c9cf` và `org.jenkins-ci.main:jenkins-bom:2.303.1`. Hai URL chính thức trả HTTP 200 qua Python. Không chọn bytekit SNAPSHOT vì thiếu provenance, NiFi vì reactor lớn và các hồ sơ Jenkins khác để giữ giới hạn hai CVE.

Công cụ: **Temurin 1.8.0_514-b01, Maven 3.9.9**, cache Maven hiện có. Package dùng `maven.test.skip=true`, `checkstyle.skip=true`, `rat.skip=true`; không coi package là bằng chứng test hoặc C7. Jenkins dùng bridge HTTP chỉ nghe loopback, lấy byte từ Maven Central/Jenkins chính thức qua Python TLS, lưu URL/status/SHA-256 cho GET; HEAD chỉ kiểm tra metadata. Không thay dependency bằng JAR khác.

Sau lượt 600 giây, source Jenkins đã biên dịch nhưng chờ `hpi:resolve-test-dependencies`. Thread dump xác nhận `TestDependencyMojo` đang tải plugin cho test harness. POM tạm của lượt PASS chỉ thêm execution `default-resolve-test-dependencies` với phase `none`, giữ các goal compile/JAR/HPI package và không thay dependency production. Đây là profile package có bỏ test staging, không phải build/test Jenkins tích hợp đầy đủ.

Một lượt bridge đầu ghi `ns0:settings` khiến Maven bỏ qua mirrors; đã dừng lượt after lặp lại, giữ receipt lỗi và sửa default namespace. Lượt tiếp theo xác minh được BOM nhưng gặp timeout với các JAR lớn; bridge được đổi sang truyền theo khối để Maven không chờ toàn bộ tệp trước khi nhận header.
